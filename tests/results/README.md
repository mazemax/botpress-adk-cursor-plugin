# Test results

This directory stores deterministic baselines, dated static evidence, and sanitized real-host results. `context-baseline.json` is generated by `npm run measure:context -- --write` and reviewed like any other upstream-facing change. Historical Stage 0–2 summaries remain unchanged.

## Real-host result format

1. Copy `stage-3-result-template.json` to a dated file ending in `.result.json`; the template itself is not a result and is not counted as one.
2. Replace every placeholder with exact package version and full package SHA, upstream version/commit, host/version/surface, OS/version/architecture, model, timestamp, and repetition count.
3. Record each executed case ID with expected behavior, observed behavior, status, repetitions, and sanitized evidence. Include run limitations and leave unexecuted cases absent or explicitly untested—never infer a pass.
4. Run `npm run check:behavior`. Actual `.result.json` files are checked for known case IDs, matrix surfaces, revisions, and environment metadata.
5. Update `tests/compatibility/matrix.json` only from observed evidence. A `tested` row needs evidence for install, discovery, activation, workflow, update, rollback, and uninstall; failed or blocked evidence must remain visible.

Never store secrets, real PATs, private project content, customer data, full sensitive transcripts, or reviewer credentials. Do not publish percentages without the associated environment and repetition metadata. No real-host `.result.json` file currently exists.
